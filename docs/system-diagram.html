System Architecture · Reference

SMSOne — a Spring Modulith behind a reactive edge

A multi-tenant platform: 23 domain modules inside one deployable, fronted by a stateless reactive API gateway that owns the edge. This page is the detail map — every filter in order, every limiter with its algorithm, every store with what actually lives in it, top to bottom.

01

The whole system, top to bottom

Clients enter through the gateway; the gateway shapes traffic and proxies /api/v1/** to the modulith over a load-balanced connection plus three secret-authed seams; the modulith commits state and an event outbox in one transaction; async consumers fan out; every layer shares the stores at the bottom.

The edge pipeline — every stage, in execution order

One request through the gateway. Left: the filter and its global order. Right: how it fails and what backs it. Everything above routing runs for every request; the traffic stages apply per-route from its TrafficPolicy.

global Request identity & trace — mints gw-<uuid> request id + W3C traceparent; both propagate to the backend and every log line. headers
│▼
+10 EdgeAuthorization — Bearer JWTs validated against Keycloak's JWKS (cached, no IdP round-trip); X-Api-Key resolved via the modulith introspection seam. Enforces the route's AuthPolicy: authenticated · required scopes · tenant-path template (path tenant must equal token tenant). Denials → security log + edge-audit seam. 401 / 403JWKS · seam
│▼
+15 Plan quota — fixed-window counter: INCR gwquota:<tenant> + EXPIRE on first hit of the window; ceiling = the org's api.requests.per_minute entitlement fetched through the quota seam. The commercial ceiling, distinct from the burst limiter below. Read live by gatewayusage. 429Valkey
│▼
+20 Plugins — the extensibility seam: ordered custom filters registered by plugin modules. extension
│▼
route Route match — RouteCatalog: two tiers in one table — YAML-seeded (durable, git-reviewed) + runtime-registered via gatewayroutes (instant, survives until restart). Most-specific wins by ascending order; 8 API products; platform-api catch-all keeps ungrouped paths working. 404in-memory map
│▼
traffic Rate limiter — token bucket (SCG RedisRateLimiter): replenish 20 tokens/s, burst 40, per caller — key falls back principal → tenant → IP. Draft-IETF RateLimit-* headers on every response; a denial adds Retry-After. The burst guard, distinct from the plan quota above. 429Valkey
│▼
traffic Body cap & response timeout — requests over 10 MB refused; a backend slower than 15 s fails fast (per-route edge-api policy values). 413 / 504
│▼
lifecycle Lifecycle enforcement — DEPRECATED still serves but stamps Deprecation + Sunset headers; RETIRED never reaches the backend. The dev portal's changelog renders this table live. 410 Gone
│▼
cache Edge response cache — SCG LocalResponseCache (in-process), GETs only, per-route TTL; the stock URI+cookie key is replaced by a tenant-aware @Primary CacheKeyGenerator so tenants can never read each other's cached responses. hit → no proxy
│▼
resilience Circuit breaker — Resilience4j per route: sliding window 4 calls, trip at ≥50% failures, OPEN holds 1s then HALF-OPEN probes; while open, the fallback controller answers instead of the backend. Retries: idempotent GETs only, on 5xx — a write is never replayed. 503 fallback
│▼
balance Load balancer — Spring Cloud LoadBalancer (lb:// via a registry-backed reactive discovery client): round-robin across each service's instances from the service registry; per-service health-path (/actuator/health). One backend today — the seam is where the modulith splits later. round-robin
│▼
egress Proxy → backend — response flows back through gzip compression and the separable log streams (access · security · error); OTel span + Prometheus counters close out. 200…

Admin plane (:29090, never routed publicly): gatewayroutes (CRUD + lifecycle + auth/rate flags) · gatewaycatalog · gatewayopenapi · gatewayusage · Prometheus. Inside the modulith — the request chain, exact order

The gateway already authenticated the token; the modulith re-validates it (defense in depth) and then runs its own ordered servlet chain — each filter one concern, each with a named refusal.

MAX_PREC RequestId — adopts the gateway's gw-… id (or mints one); it becomes meta.requestId in every envelope. headers
│▼
−100 Security chain — JWT resource server (Keycloak issuer, audience smsone-api); identity keys on the subject, never the username; realm roles expand through the hierarchy (superadmin → admin → support). 401
│▼
−2 Impersonation — X-Impersonate: <session> swaps the effective principal; session validity re-checked every request; audit rows name the operator with onBehalfOf. 403
│▼
−1 Org MDC — stamps the effective org/tenant into the log context, so even a 429 two steps later is attributed. logging
│▼
0 App rate limit — distributed window counters on Valkey, tenant-scoped keys, split policies: reads 600/min, writes 60/min (defaults). Second line behind the edge bucket — protects the DB tier even from inside traffic. 429Valkey
│▼
1 Idempotency — Idempotency-Key replays the stored response for same principal+key+body (24 h); same key, different body refuses. A replay still spends a rate-limit token (order 0 first) on purpose. 409Valkey
│▼
2 Provisioning gate — no-JIT: a valid JWT alone is not access; the subject needs an app_user row. GET /api/v1/me is the one exception so onboarding is visible. 403 NOT_PROVISIONED
│▼
3 Org security policy — the tenant's own tightening: IP allowlist (CIDR), trusted-device requirement (X-Device-Id), session max-age. Refusals name the rule; the policy endpoints themselves are always reachable (no lockout). 403 (named rule)
│▼
4 Maintenance — during a RESTRICT window the org's writes answer 503 + Retry-After; reads pass; ANNOUNCE is banner-only. 503
│▼
5 Subscription access — a PAUSED subscription (lapsed trial) makes the org read-only: org-scoped writes refuse, the billing surface stays open as the pay-to-recover path. 402 PAUSED
│▼
ctrl Controller — @PreAuthorize hasPermission(orgId, 'organization', '<perm>') fine-grained RBAC (permission union of role + groups, cached), entitlement gates with upgrade-shaped 403s, then the service layer. Every response: one JSON:API envelope, data ⊻ errors, always meta.requestId. envelope

06

Async plane — outbox, listeners, jobs

State change and event publication commit in the same transaction (Spring Modulith's JDBC event publication registry — a transactional outbox in Postgres). Listeners run after commit, async, each in its own transaction; an incomplete publication is re-delivered, so a consumer outage defers work instead of losing it.

TX Write + publish atomically — e.g. OrganizationRegistered, SubscriptionChanged, MemberRemoved land in event_publication with the domain rows. Postgres
│▼ after commit, async, at-least-once
consumer Webhook dispatcher — per-org subscriptions; payload signed HMAC-SHA256 (X-Webhook-Signature); at-least-once with backoff → dead-letter after max attempts (5); secrets AES-GCM at rest, full value shown once; delivery log per subscription; per-org retention override. → customer endpoints
consumer Exchange workers — imports/exports as jobs: batch-committed, resumable after a crash from the last committed batch, idempotent handlers (proven: 100k rows with a mid-run kill → exactly 100k effects); row-addressed error reports; cron schedules run as their owner. S3 + Postgres
consumer Billing listeners — on org registration: auto-provision the Kill Bill account (idempotent, race-safe) and start the trial-on-signup (PRO 30d, skipped if a plan was already assigned). Kill Bill pushes payment/subscription events back → reconcile into entitlements (the one write direction). Kill Bill
consumer Search indexer · notifications — projections into Postgres FTS; in-app + email/SMS sends resolved through the integration hub's effective provider (org override wins over platform default). Postgres · SMTP
│ scheduled, cluster-locked
jobs Scheduler — DB lock rows make every job single-flight across instances (observable at /admin/scheduler/locks): trial expiry (TRIALING → PAUSED), retention purges (webhook deliveries, exchange jobs, soft-deleted rows — per-org overrides honored, legal holds always skipped), billing reconcile. Postgres locks
07

Data & caching plane — what lives where

Five stores, each with one job — plus a two-level cache in front of the hot reads.

Postgres 18

system of record
  • Every module's tenant data (Flyway-migrated, one schema)
  • event_publication — the transactional outbox
  • Full-text search: websearch_to_tsquery + pg_trgm typo fallback (p95 ~35ms @ 100k docs)
  • Soft deletes + nightly purge at retention (legal holds skip)
  • Scheduler lock rows — clustered single-flight jobs

Valkey 8

shared fast state — key namespaces
  • Edge token buckets — SCG rate limiter (20/s, burst 40)
  • gwquota:<tenant> — plan-quota fixed windows
  • App rate-limit windows — per-tenant read/write counters
  • Idempotency replay store — 24 h response snapshots
  • L2 cache + pub/sub invalidation channel (below)

SeaweedFS

s3 object store
  • Personal + org files, document catalogs
  • Exchange artifacts: uploads, results, row-error reports
  • Reads hand out short-lived presigned URLs (302) — bytes never proxy through the app

Kill Bill 0.24 + MariaDB

billing engine · kaui :29095
  • One KB tenant = the platform (smsone); one KB account per org (externalKey = orgId)
  • Catalog plans pro-monthly / enterprise-monthly; subscriptions → invoices → payments
  • Push notifications → /api/v1/billing/killbill/notifications → reconcile standing (ACTIVE ↔ PAST_DUE) into entitlements
  • Payment methods via KB plugins — raw card data never touches the platform

DuckDB (embedded)

analytics mart
  • In-process OLAP — a durable mart file shared by all in-process connections
  • Long refreshes run on their own connection so KPI reads never block
  • Curated report catalog surfaced at /api/v1/analytics/reports

Keycloak 26 (its own store)

identity data
  • Realm smsone imported at boot (displayName ← BRAND_NAME)
  • Users (pinned platform admin), KC Organizations per tenant, realm roles
  • Dev-mode store lives in-container — a recreate re-imports the realm

The two-level cache (shared kernel, backing entitlements, permissions, settings…): L1 is per-node Caffeine, L2 is shared Valkey; a pub/sub invalidation channel drops peer L1s on write; L2 failure degrades to L1-only (never an outage); striped locks bound the stampede on cold keys.

read L1 Caffeine (per node, ns access) → miss → L2 Valkey (shared; first node to load publishes, peers' cold reads hit L2 not the DB) → miss → loader (DB) under a striped lock → write-through L2 then L1. hit path
write Invalidate — evict + publish on the invalidation channel → every other node drops its stale L1 entry; a plan change bites the very next gate check, not a TTL later. pub/sub

Identity plane & the two authority axes

Keycloak :28081

the idp
  • Realm smsone; two-column smsone login + email theme; product name env-driven (BRAND_NAME)
  • smsone-web — public client, PKCE required, localhost:* redirects, post-logout registered
  • smsone-admin — service account (manage-users + view-realm) used by provisioning
  • KC Organizations: one per tenant → the token's organization/tenant claim
  • JWKS consumed twice: gateway (edge validation) and modulith (defense in depth)

Two disjoint axes

authorization model
  • Platform: realm roles, hierarchical — support → admin → superadmin; guards /admin/**
  • Organization: per-tenant permissions (member:invite…), role ∪ groups, escalation guard (grant only what you hold)
  • A platform role grants zero org permissions — crossing is impersonation, audited, TTL-bound
  • Machine access: org API keys = a subset of the minter's permissions, SHA-256 stored, prefix+secret shown once, rotation

Portal sessions

:3001 / :3002
  • Edge middleware gate → OIDC code + PKCE → tokens in httpOnly cookies
  • Silent refresh in middleware; sign-out ends the KC session (post-logout redirect)
  • Try-it proxies server-side: session token attached out of the cookie — credentials never in page JS
