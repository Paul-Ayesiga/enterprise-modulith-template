System Architecture · Reference

SMSOne — a Spring Modulith behind a reactive edge

A multi-tenant messaging platform: 23 domain modules inside one deployable, fronted by a stateless reactive API gateway that owns the edge — auth, traffic, observability, and API management — so every service speaks one front door. The whole system, in one diagram.

23 modulith modules 7 gateway phases shipped edge :8090 · admin :9090 · api :8080 hexagonal · ports & adapters

The whole system

Clients enter through the gateway; the gateway proxies /api/v1/** to the modulith and reaches it over three thin, secret-authed seams; every module shares the infrastructure below.

03

The edge, phase by phase

Seven shipped phases. Each route opts into what it needs by configuration — predicates, auth, traffic, transform, lifecycle, product — with no code.

1 · Core

routing
  • Predicate routing (path/host/header/method/query), reverse proxy
  • Request-id + one error envelope for edge failures

2 · Security

who are you
  • Bearer JWT validated against Keycloak JWKS — no platform call
  • Coarse authZ; API-key introspection + internal service tokens

3 · Traffic

protect & shape
  • Rate-limit · timeout · request-size · circuit-breaker · retries
  • Tenant-safe cache, load-balancing, gzip compression

4 · Observability

measure
  • Prometheus metrics; W3C trace propagation gateway→service
  • Separable access / security / error log streams; edge audit sink

5 · Extensibility

program it
  • Request/response transforms; a plugin framework
  • Dynamic routes (no restart); WebSocket; named reusable policies

6 · Administration

operate
  • Admin API on a separate port; per-consumer quotas from the plan
  • API-key rotation; service discovery auto-registers a backend

7 · Enterprise

API management
  • Lifecycle (published/deprecated→Sunset/retired→410) + versioning
  • API products, catalog, and published OpenAPI
04

The pipeline order

Global filters run in this order for every request; a retired version 410s before auth, and quota is metered after identity is known.

request-id +0→ trace +1→ access-log +2→ lifecycle +5→ auth +10→ quota +15→ plugins +20→ routing proxy
05

The platform — 23 modules

One Spring Modulith deployable. Each module owns its data and exposes only its published ports; boundaries are enforced by ModularityTests.

Identity & Access

who & what they may do
  • identity — users, provisioning, Keycloak sync
  • access — roles, permissions, org authorization
  • apikeys — machine credentials (mint / rotate / revoke)
  • profile — the caller's own record, devices, consent

Tenancy & Commercial

orgs & money
  • organization — tenants, members, groups, lifecycle
  • subscription — plans, entitlements, edge quotas
  • billing — invoices, proxied from Kill Bill

Comms & Events

reaching out
  • notification — in-app + email (SMTP)
  • webhooks — signed, retried outbound event delivery

Data movement

in & out
  • exchange — background import/export jobs + schedules
  • files — object storage (SeaweedFS), presign
  • document · search — rendering & lookup

Ops & Governance

running it safely
  • audit — append-only who/when/what trail
  • compliance — legal holds, erasure (GDPR)
  • maintenance · scheduler · analytics
  • support · settings · integration · localization

Shared kernel

the spine
  • JSON:API envelope + meta.requestId on every response
  • Security context, cursor pagination, persistence base
  • The AuditLog port every module records through
06

Infrastructure & the seams

The gateway and the modulith share Valkey and the OTel collector; everything else the platform owns. The three control seams are thin HTTP endpoints, each backed by an existing platform port.

Data & identity

stores
  • Postgres — every module's tenant data
  • Keycloak — the IdP; issues JWTs, serves JWKS
  • Valkey — cache, rate-limit & quota counters (shared)

Objects, mail & billing

services
  • SeaweedFS — S3-style object store for files
  • Mailpit / SMTP — outbound email
  • Kill Bill — subscription billing engine
  • otel-lgtm — traces / metrics / logs collector

Gateway ⇢ platform seams

gateway-secret, @Hidden
  • /internal/gateway/api-key/introspect → ApiKeyAuthenticator
  • /internal/gateway/audit → AuditLog.recordExternal
  • /internal/gateway/quota → Entitlements.limitOf
