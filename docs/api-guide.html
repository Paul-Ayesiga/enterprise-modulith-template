1 · Authentication

Every call carries a Keycloak bearer token minted for this API (audience smsone-api). Dev shortcut: make token or scripts/api.sh. Raw flow (password grant, dev realm):

curl -s http://localhost:8081/realms/smsone/protocol/openid-connect/token \
  -d grant_type=password -d client_id=smsone-web \
  -d username=paul -d password=Paul123 | jq -r .access_token
Two disjoint authority axes. Platform realm roles (platform-support → platform-admin → platform-superadmin) reach platform surfaces; org permissions (like member:invite) reach tenant surfaces. A platform role grants zero org permissions — crossing over is impersonation's job.
Org-scoped tokens & switching orgs. Tenant calls need the token's Keycloak organization claim to name the org in the path — a token scoped to org A gets 403 on org B even if the user is a member of both. A dual member "switches" by requesting a token scoped to the other org; the server never trusts a client-asserted active org.

No-JIT: a valid JWT alone is not access — the subject also needs a provisioned app_user row (403 ACCOUNT_NOT_PROVISIONED otherwise). GET /api/v1/me is the one gate exception.

2 · The envelope, request ids, localized errors

Every JSON response is one envelope: data XOR errors, always meta.requestId (also the X-Request-Id header — quote it in bug reports).

{ "data": { "id": "org.example", "type": "setting",
            "attributes": { "key": "org.example", "value": "42" } },
  "meta": { "requestId": "01J4X9GVJ4C1T4V0V3S8B7NQZD" } }
{ "errors": [ { "id": "01J4X9…-1", "status": "422", "code": "VALIDATION_FAILED",
                "title": "Validation failed", "detail": "cron must be a valid six-field Spring cron expression (e.g. '0 0 2 * * *').",
                "source": { "pointer": "/data/attributes/cron" } } ],
  "meta": { "requestId": "01J4X9…" } }
  • Prefer RFC 9457? Send Accept: application/problem+json — same data, standard shape.
  • Localized details: send Accept-Language: fr; when the translation catalog holds error.<code> (e.g. error.resource_not_found) the detail localizes; otherwise you get the English original.
  • Stack traces never reach the wire. A 500's detail is generic; the trace lives in the server log under your request id.

3 · Cursor pagination

Collections page by keyset cursor — no page numbers, no totals (by design). Parameters are literally page[size] and page[after] (encode the brackets or use scripts/api.sh, which does).

GET /api/v1/orgs/6a1f…/exchange/jobs?page[size]=2

{ "data": [ { "id": "…", "type": "exchange-job", "attributes": { … } },
            { "id": "…", "type": "exchange-job", "attributes": { … } } ],
  "meta": { "requestId": "…",
            "page": { "size": 2, "count": 2, "hasMore": true,
                      "nextCursor": "Y3JlYXRlZEF0PXQ6MjAyNi0wOC0wMVQwNzoxNTo0Mlp8aWQ9dTo…" } },
  "links": { "next": "…?page[size]=2&page[after]=Y3JlYXRlZEF0…" } }

Follow links.next until hasMore is false. Cursors are opaque and collection-specific — replaying one against another collection is a 422, not a 500.

4 · Rate limits

Tenant-keyed token buckets on /api/** (writes 60/min, reads 600/min by default). Every response carries the draft-IETF headers; a denial is 429 RATE_LIMITED with Retry-After:

RateLimit-Policy: "read";q=600;w=60
RateLimit: "read";r=597;t=60
X-RateLimit-Remaining: 597

5 · Idempotency keys

Any unsafe request may carry Idempotency-Key: <your-uuid>. Same principal + same key + same body ⇒ the stored response replays; same key with a different body ⇒ 409. Keys live 24h.

6 · Tenant lifecycle (platform axis)

Full story: docs/TENANT_LIFECYCLE.md. The operator flow:

# create (platform-admin) — provisions Keycloak org + first OWNER (invite email via Mailpit :8025)
curl -X POST :8080/api/v1/orgs -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"alias":"acme","name":"Acme Ltd","ownerEmail":"owner@acme.test","ownerFirstName":"Ada","ownerLastName":"Owner"}'
# → 201 {"data":{"id":"6a1f22b0-…","type":"organization","attributes":{"alias":"acme","status":"ACTIVE",…}}}

# observe the fleet (platform-support)
GET /api/v1/admin/orgs?status=active&page[size]=20
GET /api/v1/admin/orgs/{orgId}            # one record
GET /api/v1/admin/orgs/{orgId}/members    # read-only roster (subjects + role codes)

# lifecycle (platform-admin)
POST   /api/v1/orgs/{orgId}/suspend       # reversible; every member's access dies immediately
POST   /api/v1/orgs/{orgId}/reactivate
DELETE /api/v1/admin/orgs/{orgId}         # ONLY from SUSPENDED (409 otherwise); soft + audited,
                                          # fans out the org.deleted webhook

7 · Members, roles, permissions (tenant axis)

# the fixed permission vocabulary (any authenticated caller)
GET /api/v1/permissions        # → [{"id":"member:invite","type":"permission",…}, …]

# invite (member:invite) — idempotent re-invites return the existing membership
POST /api/v1/orgs/{orgId}/members
{"email":"jo@acme.test","firstName":"Jo","lastName":"Kintu","roleCode":"MEMBER"}

# custom role (role:create) — permission NAMES come from the catalog above
POST /api/v1/orgs/{orgId}/roles
{"code":"AUDITOR","name":"Auditor","permissions":["org:read","audit:read"]}
The escalation guard. You can only grant permissions you hold. Inviting someone into a role carrying member:remove when you lack it: 
403 {"errors":[{"code":"FORBIDDEN",
  "detail":"You cannot grant permissions you do not hold: member:remove"}]}
The same rule guards exchange imports — evaluated against the requester at processing time.

8 · Plans & entitlements

GET /api/v1/admin/plans                      # seeded catalog (support)
# → FREE / PRO / ENTERPRISE; entitlements: null value = feature on, number = cap, absent = off/unlimited

PUT /api/v1/admin/orgs/{orgId}/subscription  # assign (platform-admin, audited)
{"plan":"PRO"}

GET /api/v1/orgs/{orgId}/subscription        # the tenant's own view (org:read)
# → {"attributes":{"planCode":"PRO","status":"ACTIVE",
#     "entitlements":{"exchange.enabled":null,"members.max":250,"webhooks.max":50,"exchange.schedules.max":25}}}

Gates fire with upgrade-shaped 403s, before side effects:

403 {"errors":[{"code":"FORBIDDEN",
  "detail":"Your organization's plan allows 25 for 'members.max' and that limit is reached. Upgrade the plan to add more."}]}

A plan change bites the next request (cache evicted through SubscriptionChanged) and fans out the org.subscription_changed webhook.

9 · Billing (Kill Bill)

Kill Bill (:8082, Kaui UI :9095) is the billing system of record; entitlements above stay the single authority — billing events reconcile into them. Set BILLING_BOOTSTRAP=true for the dev tenant + catalog.

POST /api/v1/admin/orgs/{orgId}/billing/account        # link (platform-admin, idempotent)
POST /api/v1/admin/orgs/{orgId}/billing/subscription   # {"plan":"PRO"} → 202; entitlements reconcile
GET  /api/v1/admin/orgs/{orgId}/billing                # balance + live KB subscriptions + payment methods
GET  /api/v1/orgs/{orgId}/billing/invoices             # the tenant's invoices (org:read)
# → [{"id":"8c0e…","type":"invoice","attributes":{"invoiceNumber":"1001","amount":49.00,
#      "balance":0.00,"currency":"USD","invoiceDate":"2026-08-01","status":"COMMITTED"}}]

Payment failure → subscription standing flips to PAST_DUE (entitlements kept — a grace); recovery → ACTIVE; cancellation reconciles to FREE. Adding a payment method is Kaui's / a KB payment plugin's job; the billing view lists what's on file.

10 · Documents & files

# upload into the org (document:manage; multipart field "file")
curl -X POST :8080/api/v1/orgs/{orgId}/documents -H "Authorization: Bearer $TOKEN" -F file=@board-report.pdf
# → 201 {"attributes":{"name":"board-report.pdf","source":"UPLOAD","sizeBytes":48211,…}}

GET    /api/v1/orgs/{orgId}/documents          # paged catalog (document:read)
GET    /api/v1/orgs/{orgId}/documents/{id}     # 302 → short-lived presigned URL; follow it for bytes
DELETE /api/v1/orgs/{orgId}/documents/{id}     # bytes now, metadata row soft-remains (the trail)

Personal equivalents under /api/v1/documents (owner-scoped; support may read, admin may delete). Raw object storage lives under /api/v1/files. Exchange artifacts appear in this catalog with source: "EXCHANGE".

11 · Search

GET /api/v1/orgs/{orgId}/search?q=board+report&page[size]=10       # org:read; tenant cut inside the SQL
GET /api/v1/admin/search?q=ada&org={orgId}                          # platform-support; org filter optional
# hit → {"id":"…","type":"search-hit","attributes":{"entityType":"document","title":"board-report.pdf","rank":0.60}}

Full-text first (websearch_to_tsquery), trigram fallback for prefixes/typos — so q=repor still finds the report. Measured gate: p50 ~20ms / p95 ~35ms over 100k documents.

12 · Exchange — imports & exports at scale

Import/export is jobs, never long requests. Formats: CSV, JSONL, XLSX, XML (+ zipped sources). Submitting needs the handler's own permission (e.g. org-members imports need member:invite).

Walkthrough: bulk member import

# 1 — discover handlers & download the template
GET /api/v1/exchange/handlers
# → {"id":"org-members","attributes":{"importPermission":"member:invite","exportPermission":"member:read",
#     "header":["email","firstName","lastName","roleCode"],"templateVersion":1,"formats":["CSV","JSONL","XLSX","XML"]}}
GET /api/v1/exchange/handlers/org-members/template?format=CSV   # ready-to-fill file

# 2 — fill it
cat members.csv
email,firstName,lastName,roleCode
jo@acme.test,Jo,Kintu,MEMBER
bad-address,Bad,Row,MEMBER
amina@acme.test,Amina,Okello,ADMIN

# 3 — submit (202: it's a background job)
curl -X POST ":8080/api/v1/orgs/{orgId}/exchange/imports?handler=org-members&format=CSV" \
  -H "Authorization: Bearer $TOKEN" -F file=@members.csv
# → 202 {"data":{"id":"9f6c818b-…","type":"exchange-job","attributes":{"status":"PENDING",…}}}

# 4 — poll
GET /api/v1/orgs/{orgId}/exchange/jobs/{jobId}
# → {"attributes":{"status":"COMPLETED_WITH_ERRORS","processed":2,"failed":1,
#     "handler":"org-members","handlerVersion":1,…}}

# 5 — the row-addressed error report (302 → CSV)
GET /api/v1/orgs/{orgId}/exchange/jobs/{jobId}/report
row_number,error
2,email is not a valid address: bad-address

row_number counts data records from 1 (header excluded). The requester also gets an in-app "your import finished" notification, and subscribed webhooks receive org.exchange.job_completed.

Exports & schedules

POST /api/v1/orgs/{orgId}/exchange/exports   {"handler":"org-members","format":"XLSX"}   # → 202
GET  /api/v1/orgs/{orgId}/exchange/jobs/{id}/result                                      # 302 → the file

# recurring export (cron is six-field Spring cron, UTC); fires AS you — revoking your permission disables it
POST /api/v1/orgs/{orgId}/exchange/schedules {"handler":"org-members","format":"CSV","cron":"0 0 2 * * *"}
POST /api/v1/orgs/{orgId}/exchange/jobs/{id}/cancel     # best-effort, batch-boundary
Scale semantics worth testing: a crashed/reclaimed import resumes from its last committed batch (at-least-once delivery into idempotent handlers — the suite proves 100k rows with a mid-run kill produce exactly 100k effects); data errors never burn retries; infra errors retry with backoff then FAIL with a curated message.

13 · Webhooks (outbound)

GET /api/v1/webhooks/event-types      # the subscribable vocabulary, with descriptions

POST /api/v1/orgs/{orgId}/webhooks    # webhook:manage
{"url":"https://hooks.acme.test/smsone","events":["org.member.added","org.exchange.job_completed"]}
# → 201 {"attributes":{"secret":"whsec_9f3c1a…full-secret-shown-ONCE…",…}}   ← store it now; reads mask it

Verifying a delivery

POST https://hooks.acme.test/smsone
X-Webhook-Event: org.member.added
X-Webhook-Signature: sha256=88e2c4…

{"event":"org.member.added","orgId":"6a1f…","occurredAt":"2026-08-01T07:15:42Z",
 "subject":"kc-7d2e…","role":"MEMBER"}

# verify: HMAC-SHA256 over the EXACT raw body with your secret
echo -n "$RAW_BODY" | openssl dgst -sha256 -hmac "$WHSEC" -hex   # must equal the header after "sha256="

Delivery is at-least-once with backoff → dead-letter after 5 attempts; secrets are AES-GCM encrypted at rest; per-subscription delivery log at …/webhooks/{id}/deliveries.

13b · API keys (machine access)

Call the API without a human token. An org key carries a subset of your permissions (never more); a platform key is support-tier and read-only.

# mint (apikey:manage) — secret shown ONCE
POST /api/v1/orgs/{orgId}/api-keys   {"name":"ci-bot","permissions":["org:read","member:read"]}
# → 201 {"attributes":{"prefix":"sk_9f3c1a2b","secret":"sk_9f3c1a2b.6d4e…full…","permissions":["org:read","member:read"]}}

# use it — instead of the bearer token
curl :8080/api/v1/orgs/{orgId}/members -H "X-Api-Key: sk_9f3c1a2b.6d4e…full…"

DELETE /api/v1/orgs/{orgId}/api-keys/{id}     # revoke — the next call 401s immediately

A bad key authenticates nothing (you get a plain 401, never confirmation that a prefix exists). Secrets are stored SHA-256-hashed. Platform keys live under /api/v1/admin/api-keys.

16 · Impersonation (the audited bridge)

POST /api/v1/admin/impersonations       # platform-support; WRITE mode needs platform-admin
{"targetSubject":"kc-7d2e…","orgId":"6a1f…","reason":"Ticket #4812 — member cannot see documents","ttl":"PT15M"}
# → 201 {"data":{"id":"3e7a…","type":"impersonation-session",…}}

# wear it: add the header to any TENANT call (platform routes refuse it — a session carries no platform authority)
GET /api/v1/orgs/6a1f…/documents
X-Impersonate: 3e7a…

DELETE /api/v1/admin/impersonations/3e7a…    # end early; expiry also ends it — re-checked EVERY request

18 · Tester tips

  • make run boots app + full stack; make seed adds the acme demo org. Mailpit (:8025) catches invite emails; Grafana (:3000, folder SMSOne) shows the platform's own counters — dead-letters, 429s, exchange throughput.
  • Async assertions: submits answer 202; poll the job resource rather than sleeping. Webhook/notification deliveries are background workers — the delivery log endpoints are your observability.
  • Repro reports: include meta.requestId, and for exchange the job id — every server log line for the run carries both (plus org_id).
  • The whole test suite runs on real containers (./gradlew test) — Postgres, Keycloak, SeaweedFS, Valkey, Kill Bill. No mocks of infrastructure, so what passes here behaves the same against the compose stack.
