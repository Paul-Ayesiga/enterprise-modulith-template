MCP · Model Context Protocol · the agent surface

Agents talk to the platform — through the same doors as everyone else

The platform serves the Model Context Protocol at /mcp, so AI agents (Claude Code, Claude Desktop, the Claude API's MCP connector, Managed Agents, any MCP client) can read and operate a tenant's slice of the platform. The design has one sentence at its core: MCP is a second protocol surface over the same module ports the REST controllers use — every permission, guard, transaction and audit rule exists exactly once, and both surfaces cross it.

01 — OrientationWhat this is: a transport, not another backend

Nothing about the business changed. The mcp module owns tool definitions and dispatch; it owns no capability. Tool handlers are one-line delegations to module ports, and those ports delegate to the same internal services REST delegates to.

Why stateless streamable HTTP

Each MCP request is a plain JSON-RPC POST — no Mcp-Session-Id, no SSE listening stream, no in-memory session map. That is what makes the surface safe across the modulith's N replicas with no sticky routing, and it matches where the protocol is heading (the 2026-07-28 spec RC removes sessions from streamable HTTP entirely). The trade, accepted knowingly: no server-initiated messages (sampling, elicitation, notifications) — none of which tools/resources/prompts need.

02 — Ten minutesConnect an agent

One credential works everywhere: an org API key (minted in the console or via POST /api/v1/orgs/{orgId}/api-keys, permissions capped to what the minter holds). Send it as X-Api-Key or as Authorization: Bearer sk_… — both spellings authenticate identically.

Claude Code (this repo ships .mcp.json)

{
  "mcpServers": {
    "smsone-local": {
      "type": "http",
      "url": "http://localhost:28090/mcp",
      "headers": { "X-Api-Key": "${SMSONE_API_KEY}" }
    }
  }
}

Export SMSONE_API_KEY=sk_…, start the stack (make up && make run && make gateway), open Claude Code in the repo — the server appears with the tools your key allows. :28090 is the gateway, the same edge production uses (https://api.<host>/mcp); running only the modulith? Point at it directly on :28080 — same behavior, minus the edge policy.

03 — IdentityAuth & scoping: the key is the whole model

  • Org-implicit, always. A key belongs to exactly one organization; no tool takes an orgId argument. Cross-tenant addressing is not a forbidden input — it is an input that does not exist. Prompt injection cannot name another tenant.
  • The permission subset is the scope model. Keys are minted with a subset of organization.Permission codes, capped by what the minter holds. Every tool declares the same permission its REST twin requires — one vocabulary, both surfaces.
  • Discovery is filtered; the call is the boundary. tools/list shows only tools the key may call (agents plan with real capabilities instead of discovering them by 403). A hidden tool invoked directly is re-checked and denied — fail closed, before any side effect.
  • Bearer sk_… is understood at both tiers. Remote MCP clients can only send bearer headers; the gateway routes sk_-prefixed bearers to key introspection, the modulith's key filter consumes them before the JWT machinery ever sees them. A JWT can never start with sk_, so nothing real is hidden from the JWT path.
  • Machine grants stay un-escalatable. When a key invites or re-roles a member, the escalation guard treats the key's minted subset as its held set — capped at mint by a human who held those permissions, so a key can hand on at most what its minter could have. A role carrying anything beyond the subset refuses.
  • Attribution is honest. Everything a key does is recorded as key:<id> — job requesters, ticket openers, audit actors.

04 — AnatomyThe request path

The gateway policy is deliberate

edge-mcp, not edge-api: a tool call may legitimately run longer than an interactive API call (60 s vs 15 s), while JSON-RPC bodies never justify 10 MB (2 MiB cap). Both halves are pinned by ShippedRouteTableTest.

05 — One policy pointThe dispatch pipeline

Every tools/call crosses one pipeline in McpToolDispatcher — the only place authorization, tenancy policy, write-gating, audit and metrics happen. Handlers never see an unauthorized call.

06 — The surfaceTool catalog — 35 tools, 8 modules

Every tool carries spec-standard safety annotations (readOnlyHint / destructiveHint / idempotentHint) plus _meta with smsone/toolVersion and smsone/area. Permissions are copied from the REST controllers' hasPermission gates — twin surfaces, one vocabulary. A tool is never renamed; breaking schema changes bump its version.

07 — Agent contentPrompts & resources

Prompts — worked procedures, few by design

diagnose_failed_webhooks — walk the delivery log, separate receiver bugs from signature disputes, redeliver only after the fix. usage_review — usage vs entitlements, flag anything past 80% of a cap.

Resources — drift-free reference

smsone://guide/agent (conventions, bundled in the jar) · smsone://reference/permissions and smsone://reference/webhook-events — rendered from the enums on every read, so they cannot rot.

08 — ContractConventions every tool honors

  • Request id, always. Every result and error carries the requestId (_meta["smsone/requestId"] and inside error payloads) — the same correlation id the REST envelope returns, joinable to server logs.
  • Errors are the REST vocabulary. error.code is a stable ErrorCode name (FORBIDDEN, VALIDATION_FAILED, SUBSCRIPTION_PAUSED, …) with a curated, client-safe detail. Never a stack trace, never an internal message.
  • Cursors, no totals. Collections take page_size (≤ 100) / page_after and return page.nextCursor — the house keyset pagination on a new wire.
  • Payload ceiling. A result stays small; bulk data moves as short-lived URLs (documents, export results), never through tool results.
  • Secrets shown once. webhook_create / webhook_rotate_secret return the signing secret exactly once, marked SENSITIVE in the description; reads mask it forever after.

10 — OpsOperating it

  • Metrics. smsone.mcp.tool.calls{tool,kind,outcome} (ok · denied · guard_maintenance · guard_subscription · error) and smsone.mcp.tool.duration{tool} — top tools, slowest tools, denied tools, failure mix. Caller identity is deliberately NOT a metric tag (unbounded cardinality); who-did-what lives in logs (requestId + key:<id> in MDC) and, for mutations, in audit_log (mcp.tool_invoked).
  • Kill switch. app.mcp.enabled=false REFUSES every request with a named JSON-RPC error rather than unregistering the servlet — a vanished route reads as version skew; a named refusal reads as what it is (the impersonation-switch rule).
  • Rate limits. Gateway token bucket on the route, plus the app-side mcp tier — a per-key bucket (one org may run several agents; a runaway one shouldn't starve its siblings).
  • Revocation is immediate. Keys verify against the live row on every request; a revoked key's very next call is a 401.

11 — ProofHow it is tested

House rules (ADR 0003): real containers, no mocks below the module edge. The MCP suite's harness is the real SDK client speaking streamable HTTP to the booted app — protocol, gateway-less auth path, dispatcher and ports exercised as one loop, with keys minted by the production hashing scheme straight into Postgres.

  • McpServerIntegrationTest — initialize → filtered tools/list → whoami; bearer spelling; 401s (missing and revoked keys); hidden-tool-called-directly denies.
  • McpGuardrailsTest — maintenance and paused-subscription refuse writes but not reads; IP allowlist gates every call; denials happen BEFORE side effects (a counting tool proves the handler never ran).
  • McpToolCatalogTest — every tool: snake_case name, version ≥ 1, area tag, real permission code, truthful safety annotations on the wire.
  • Per-phase suites — member writes under the escalation guard (from the org package, Keycloak gateway stubbed); webhook lifecycle incl. fenced redelivery; tickets + documents (storage mocked at the port, like DocumentApiTest); exchange submit-poll-cancel under handler permissions; tenant-scoped search.
  • ShippedRouteTableTest (gateway) — /mcp routes authenticated on edge-mcp with the 60 s / 2 MiB shape.

12 — EdgesBoundaries & non-goals (decisions, not gaps)

  • No API-key management tools — an agent must not rotate or mint the credential it authenticates with.
  • No platform-operator tools — impersonation and cross-tenant admin stay human + REST.
  • No role CRUD — editing permission bundles is governance; roles_list only.
  • No LLM-generated SQL — AnalyticsEngine's contract is developer-authored SQL.
  • No payment writes — money moves through Kill Bill / Pesapal flows with human consent.
  • No binary transfer — uploads are REST multipart; downloads are presigned URLs.
  • OAuth for claude.ai connectors — designed-for, deliberately later (plan phase 7): API keys serve every current client; the tool layer never looks at credentials, so OAuth arrives as one filter-level change.
